Authentication
Bearer tokens (API clients)

Send Authorization: Bearer rpr_…. Each token carries one or more scopes which nest: admin ⊃ operate ⊃ read. Tokens are minted on the Tokens page or with POST /api/v1/tokens; the plaintext is shown once and only a PBKDF2 hash is stored. Revoked or expired tokens stop working within the verification cache TTL (5 min).

Bootstrap: X-Admin-Token

A request may present the configured reaper.admin_token directly as the X-Admin-Token header. That is how the first API token is minted before any bearer exists: 

curl -s -X POST -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name": "bootstrap", "scopes": ["admin"]}' \
  http://localhost:{{ port }}/api/v1/tokens
Admin session + CSRF (browser)

/login with the admin token sets a signed session cookie. Mutating requests made with that session must also carry the CSRF token the page embeds (<meta name="csrf-token">) as the X-CSRF-Token header or a csrf_token form field. The UI's apiFetch() helper does this automatically.

Open read (api.open_read)

When api.open_read is true (currently {% if settings.api_open_read %}true{% else %}false{% endif %}) every GET endpoint marked read answers without credentials, like the other control-room dashboards. Mutating endpoints always need a bearer token or an admin session. /health, /version and /whoami are always open.

Errors

Every error is JSON {"error": "message"}: 400 bad input, 401 no credentials, 403 wrong scope or missing CSRF, 404 unknown area / entry / id, 409 the action cannot be performed right now (e.g. a scan is already running).
